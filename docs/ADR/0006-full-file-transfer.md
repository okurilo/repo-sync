# ADR 0006 — Полные изменённые файлы и автоматические проверки

Статус: принято, 2026-10-09, по запросу пользователя. Заменяет исходящий common-state/patch workflow ADR 0004; роли и ограничения Git прежние.

Репозитории уже существуют на обеих сторонах, а пользователь предпочитает надёжность независимого применения минимальному размеру patch. Outgoing сравнивает внешнюю и внутреннюю committed ветки и передаёт только выбранные изменённые файлы целиком. Неизменённый inventory исключён. Удаления по умолчанию не выбраны.

Transport protocol/schema v5 переиспользует multipart `.md` с открытым текстом и исходными бинарными вложениями. По уточнению пользователя Base64 и непрозрачное сжатие при экспорте запрещены; минифицируются только метаданные. Отступы, пробелы и переносы сохраняются побайтно. ADD/REPLACE/RENAME имеют полный payload, DELETE — intent; before hash/mode защищают удаления/переименования. Получателю не нужны общий commit/baseline. V1–v4 остаются legacy import. Выбранный изменяемый файл целиком заменяется; нет автоматического merge.

Prepare и selected Scan автоматизированы через существующую очередь IPC. Финальная запись требует явного Apply/Create; пустой Scan не создаёт отдельный экран. Secret override сохраняется отдельно от bulk keep. UI snapshot token/paths guard не публикует устаревшие результаты, ошибки не повторяются фоном.

Settings v5 не меняется: Pending.partial=true запрещает продвижение общего состояния для v4/v5. Confirmation завершает ожидание и не объявляет inventories одинаковыми. Следующий export вновь сравнивает реальные HEAD, поэтому внешние изменения должны быть закоммичены и доступны в выбранной внешней ветке. Сетевого acknowledgment нет.

Переиспользованы prepare/backup/journal/recovery, без нового persistence слоя, клиента Git или зависимостей. Обратная сторона решения: полная версия большого файла с небольшой правкой может быть больше patch без сжатия; это согласованный выбор надёжности.

## Уточнение 2026-10-14 — транспорт v6 и изображения

V6 сокращает только метаданные: files восстанавливается из records, длина полного payload берётся из size, имя/hash FILE вычисляются. Внутренняя модель и применение прежние; открытые исходные байты и хеши сохраняются. V1–v5 import остаётся. Settings v6 не меняется; никакая передача v4–v6 не продвигает common baseline.

Transient переключатель изображений с default=true сужает existing selected-path набор, исключая также удаления и оба пути переименования. Включение восстанавливает индивидуальные галочки. ENOENT attachment пропускает операцию целиком, доступный текст применяется, а локальные файлы недоступной операции сохраняются. Нет пустых заглушек, преобразования изображений, автоподбора зависимостей, новых настроек или I/O.
