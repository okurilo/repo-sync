# ADR 0006 — Полные изменённые файлы и автоматические проверки

Статус: принято, 2026-10-09, по запросу пользователя. Заменяет исходящий common-state/patch workflow ADR 0004; роли и ограничения Git прежние.

Репозитории уже существуют на обеих сторонах, а пользователь предпочитает надёжность независимого применения минимальному размеру patch. Outgoing сравнивает внешнюю и внутреннюю committed ветки и передаёт только выбранные изменённые файлы целиком. Неизменённый inventory исключён. Удаления по умолчанию не выбраны.

Transport protocol/schema v4 переиспользует multipart `.md` и compression. ADD/REPLACE/RENAME имеют полный payload, DELETE — intent; before hash/mode защищают удаления/переименования. Получателю не нужны общий commit/baseline. V1–v3 остаются legacy import. Выбранный изменяемый файл целиком заменяется; нет автоматического merge.

Prepare и selected Scan автоматизированы через существующую очередь IPC. Финальная запись требует явного Apply/Create; пустой Scan не создаёт отдельный экран. Secret override сохраняется отдельно от bulk keep. UI snapshot token/paths guard не публикует устаревшие результаты, ошибки не повторяются фоном.

Settings v5 не меняется: Pending.partial=true запрещает продвижение общего состояния для v4. Confirmation завершает ожидание и не объявляет inventories одинаковыми. Следующий export вновь сравнивает реальные HEAD, поэтому внешние изменения должны быть закоммичены и доступны в выбранной внешней ветке. Сетевого acknowledgment нет.

Переиспользованы prepare/backup/journal/recovery, без нового persistence слоя, клиента Git или зависимостей. Обратная сторона решения: полная версия большого файла с небольшой правкой может быть больше patch даже со сжатием; это согласованный выбор надёжности.
