# Локальный Security Scan

Scan вызывается на Compare и повторно перед Export. Передаваемые bytes не отправляются наружу. Snapshot/ADD/REPLACE сканируются целиком, MODIFY — декодированный реальный unified patch, включая context, добавляемые и удаляемые строки. DELETE/RENAME без payload по содержимому не сканируются. Для binary применяется консервативное UTF-8 представление; это не полный анализ бинарных форматов.

Rules: secret/password/token/apiKey/accessToken/refreshToken/clientSecret/authorization assignments; private key blocks; некоторые GitHub/AWS/API credential formats; sensitive `.env` / `.pem` / `.key` paths; email, phones, RU three-word ФИО, EN names и firstName/lastName/middleName/fullName/fio/employeeName/customerName/personName contexts. Каталоги mock/mocks/fixtures/test-data/seed/demo повышают отметку контекста. Findings формулируются как потенциальные данные, а не подтверждённые ПДн.

Renderer получает ID, file, фактическую строку исходного/целевого файла, контекст исходного текста с подсвеченным совпадением, preview, reason, severity и replacement proposal. По явному запросу пользователя найденный текст виден локально в карточках; полный приватный span остаётся в Main RAM. Для MODIFY строки patch отображаются в actual old/new file location по заголовкам hunks; replacement preview дополнительно показывает фактическую строку working file. Findings не записываются в settings, telemetry или logs.

Действия: исключить файл из уже подготовленного пакета и атомарно сохранить exclusions без нового Git I/O; показать local file в папке / открыть конкретный файл, commit и line в GitHub/GitLab/Bitbucket по HTTPS (включая распознаваемые SSH sources) по явному действию; «Оставить». Blocking findings требуют отдельного explicit override помимо «Оставить». Unknown/непринятый finding не позволяет Export. Ignored sensitive filenames блокируют даже без успешного content detection.

Local replacement: ищется единственный exact matching span в текущем локальном файле; неоднозначные случаи требуют ручного исправления. Preview показывает найденный source value, показывает replacement и предупреждает об изменении исходника. После подтверждения live bytes проверяются, заменяется только этот span, file записывается атомарно с сохранением mode. UI повторяет Git analysis / Scan. Поскольку export committed, нужно самостоятельно commit исправление, выбрать исправленный commit в профиле (если ранее выбран конкретный старый SHA) и повторить Compare. Remote replacement недоступен. Transport не редактируется скрыто.

Максимум 10 000 findings. Scanner эвристический, допускает false positives/negatives. Конфиденциальными являются также итоговые `.md`, bare Git cache и backup files; они хранятся локально с приватными правами, где поддерживает ОС.

Карточка показывает строку transport payload с исходным value и ограниченным контекстом (до 160 символов по сторонам); для patch есть отметка исходной/целевой строки. Значения в карточках не маскируются по явному запросу пользователя; для sensitive filename подсвечивается имя файла. Совпадение и контекст ограничены 160 символами; длинное совпадение помечается многоточием. Для EN name эвристики объяснено возможное совпадение с названием компонента. Исключение создаёт новый preview token, повторяет Scan/оценку размера в памяти, сбрасывает UI решения по findings и сохраняет working-tree статусы. Ошибка сохранения не меняет старый preview/settings. При last-sync Diff исключённый путь также удаляется из локального baseline inventory с новым scope; state остаётся прежним. Receiving-side scope/before проверки остаются обязательными.

### Решения и замена в пакете

Рядом с экспортом показываются причины блокировки: папка не выбрана, остались срабатывания без решения, secrets не разрешены или операция выполняется. «Игнорировать все без решения» принимает оставшиеся срабатывания и сохраняет их исходные значения в пакете. Для secrets требуется отдельное разрешение.

«Заменить на ***» изменяет только выбранное совпадение в целевых bytes пакета, сохраняет файл и пересчитывает Scan. Исходный Git и рабочие файлы не меняются. После замены решения сбрасываются; повторный Compare строит новый пакет из Git и отменяет эти замены. Для имени чувствительного файла, удалённых строк и многострочного совпадения в patch такая замена недоступна. Это явное изменение payload: проверьте, что полученный код или данные пригодны для использования.

Отредактированный пакет имеет content state вместо Git SHA. После успешной передачи для следующего автоматического last-sync Diff отправителю может потребоваться Snapshot; прямое сравнение двух Git revisions доступно по-прежнему.
