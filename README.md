# RepoSync

Приложение для синхронизации изменений между изолированными Git-репозиториями. Внутренний репозиторий получает изменения из внешнего Git и создаёт пакеты `.md`. На внешнем компьютере эти пакеты применяются к локальному репозиторию.

История Git и папка `.git` не переносятся. Коммиты и отправку изменений в Git вы выполняете самостоятельно.

## Запуск

Нужны Node.js **22.14+** и системный Git в `PATH`. Для доступа к внешнему Git настройте SSH Agent или Git Credential Manager вне RepoSync.

```sh
npm install
npm run dev
```

На главном экране нажмите «Добавить репозиторий». Тип задаётся отдельно для каждого репозитория; в одном приложении можно настроить оба типа.

- **Внутренний:** название, путь к локальному репозиторию и ветка, адрес внешнего Git и его ветка.
- **Внешний:** название, путь к локальному репозиторию и ветка. Используется для применения пакетов на внешнем компьютере.

Для выбора ветки сначала укажите папку или адрес Git, затем откройте поле ветки со стрелкой. Список загружается при первом открытии; доступны поиск и прокрутка. Под полем показаны загрузка, выбранная ветка, отсутствие веток или ошибка. После ошибки нажмите «Повторить». Выбор в RepoSync не переключает текущую ветку в Git.

В разделе «Дополнительно» доступны исключения, размер части и формат пакета. Исключения задаются шаблонами glob, по одному на строку, например `**/*.log`. По умолчанию выбран компактный формат.

## Получить изменения

Откройте внутренний репозиторий → «Получить изменения» → проверьте основу ветки или выберите другой способ сравнения → снимите галочки у файлов, которые не нужно переносить → «Проверить применение» → «Применить изменения».

RepoSync получает актуальную внешнюю ветку и применяет выбранные изменения к локальным файлам. По умолчанию отмечены все файлы diff; снимите галочки у тех, которые не нужно переносить. Файлы с галочкой при `MODIFY` целиком заменяются проверенной внешней версией, включая локальные правки внутри этого файла. Файлы без галочки и пути вне выбранного diff остаются без изменений. Частичный выбор не обновляет общее состояние синхронизации; чтобы перенести оставшееся позднее, повторите сравнение и выберите нужные файлы. Если изменяемого или заменяемого внешнего файла нет в локальном репозитории, RepoSync создаёт его из проверенного конечного состояния. Переименование из внешнего Git, если в локальном репозитории нет ни старого, ни нового пути, применяется как добавление файла под новым именем. Занятый новым содержимым локальный путь и изменённый старый файл остаются конфликтами. Перед применением создаётся резервная копия. Уже достигнутый результат пропускается: отсутствующий удаляемый файл, точное конечное содержимое или уже выполненное переименование не вызывают конфликта. После проверки исходное дерево и галочки сохраняются; операции без оставшихся изменений помечаются «Уже применено». Смена выбора требует повторной проверки. После проверки просмотр показывает локальное состояние перед применением. Отличающееся локальное содержимое при удалении или переименовании не перезаписывается.

По умолчанию выбран режим «Изменения ветки»: diff от общего предка основной и выбранной внешней веток до вершины выбранной ветки. Основа определяется по Git HEAD и всегда видна рядом с кнопкой «Сменить основу». Если Git не объявляет основу, её нужно выбрать явно; наличие main/master/develop само по себе не считается доказательством. Если выбрана сама основная ветка, смените внешнюю ветку или способ сравнения. Отсутствие общего предка и несколько общих предков требуют другого способа сравнения. Перед проверкой и применением сверяются обе вершины. Режим «По коммиту» переносит diff выбранного внешнего коммита относительно первого родителя. История доступна с поиском по SHA, названию и дате. Для merge-коммита используется первый родитель. «Между двумя коммитами» сравнивает ровно два выбранных состояния A → B: без merge-base и требования, чтобы A был предком B. Порядок выбора задаёт направление изменений. Общая история с внутренним репозиторием не требуется.

Отдельные варианты: «Сравнить репозитории целиком» сравнивает локальный и внешний committed HEAD, включая удаления внутренних файлов, отсутствующих снаружи; «От нулевого состояния» добавляет все внешние файлы, сохраняя остальные внутренние файлы и останавливаясь при несовпадении существующих. Для корневого коммита используйте нулевое состояние. Входящие изменения не проходят КБ-проверку и показываются без маскирования.

Режим ветки, выбранный коммит или диапазон переносит только свой diff и не объявляет репозитории полностью синхронизированными. Общее состояние для исходящих пакетов сохраняется после полного сравнения или переноса от нуля. Если общей точки ещё нет, первый исходящий пакет содержит выбранные файлы; общая точка сохраняется только при полном переносе.

Локальный репозиторий должен быть на ветке, указанной в настройках. После применения проверьте результат и создайте коммит перед подготовкой следующего пакета.

## Подготовить пакет изменений

Откройте внутренний репозиторий → «Подготовить пакет изменений» → выберите файлы или папки → «Проверить данные» → «Перейти к пакету». Выберите папку и нажмите «Создать пакет».

Передайте **все части `.md`**, сохранив исходные имена. На внешнем компьютере откройте внешний репозиторий → «Выбрать пакет». Выберите любую часть: RepoSync прочитает весь набор из той же папки и покажет изменения. Выберите файлы или папки, нажмите «Проверить применение», затем «Применить изменения», проверьте результат и выполните обычные операции Git.

Частичное применение и подтверждение частичного пакета не продвигают общее состояние. Пропущенные файлы остаются доступны при следующем расчёте; уже переданные операции могут снова присутствовать в diff и распознаются при проверке как достигнутые. Если получатель применяет только часть полного пакета, отправитель должен отменить ожидание вместо подтверждения полного переноса. Для частичных пакетов используйте актуальную версию RepoSync на обоих компьютерах.

После успешного применения вернитесь на внутренний компьютер и нажмите «Подтвердить применение». До подтверждения или отмены ожидания следующая синхронизация недоступна. Отмена ожидания сохраняет файлы пакета на диске и не отменяет его применение на другом компьютере.

RepoSync сам выбирает полный пакет для первичной синхронизации или пакет изменений относительно общего сохранённого состояния. Для исходящего пакета SHA и исходное состояние вручную выбирать не нужно. При первом полном применении существующие одноимённые файлы должны совпадать с пакетом: конфликтующие файлы не перезаписываются. Первый пакет изменений может восстановить исходное состояние из коммита, уже имеющегося в принимающем Git.

## Проверка данных

Синхронизация использует **файлы выбранной ветки, сохранённые в коммите**. Изменения в индексе, вне индекса и новые файлы без коммита показаны отдельно; в пакет они не входят.

КБ-проверка выполняется только при подготовке исходящего пакета. На шаге «Проверка данных» список файлов и поиск помогают просмотреть срабатывания. Галочки позволяют оставить отдельное значение, все значения файла или все найденные значения сразу. Также можно исключить файл, заменить значение в локальном исходнике или оставить его в пакете. Исключённый файл добавляется в настройки исключений и не участвует в последующих синхронизациях. Замена меняет локальный файл: после неё создайте коммит и повторите синхронизацию.

Найденные значения скрываются до передачи в интерфейс. **Скрытие в просмотре не удаляет их из пакета.** Выбор «Оставить в пакете» сохраняет исходные данные. Для включения возможных паролей, токенов и ключей нужно отдельное явное разрешение. Проверка использует правила поиска и может пропустить чувствительные данные или отметить безопасный пример; просмотрите изменения самостоятельно.

## Пакеты и просмотр изменений

Новые пакеты v3 состоят только из частей `.md`. Бинарные данные кодируются внутри пакета и могут разбиваться между частями. Компактный формат использует сжатие, когда оно уменьшает размер; читаемый хранит текст непосредственно. Оба формата сохраняют байты файлов, переводы строк LF/CRLF и права на выполнение. **Пакеты не зашифрованы.**

Во всех сценариях доступны галочки файлов и папок. Папка выбирает все вложенные операции, включая скрытые поиском или фильтрами; промежуточная галочка означает частичный выбор. Переименование выбирается целиком как старый путь → новый путь. Поиск и фильтры не меняют выбранный набор. Галочки бинарных и больших файлов доступны даже без просмотра кода. На главном экране показаны состояния репозиториев и требуемые действия без фонового сканирования.

В просмотре доступны поиск файлов, режим «В одном списке» и сравнение «Рядом». Для бинарных файлов и файлов больше 128 КБ просмотр кода недоступен. Идентификаторы состояний находятся в разделе «Подробности». Тему можно переключить в верхней панели.

## Совместимость

Настройки v1–v3 преобразуются в v4. Исходный JSON сохраняется рядом как `settings.vN.backup.json`. После обновления проверьте пути, адрес внешнего Git и тип репозитория.

Прежние раздельные исходные состояния не преобразуются в общее состояние: нужна первичная синхронизация. Старое ожидание подтверждения сохраняется. Если подтвердить применение невозможно, отмените ожидание и создайте пакет заново.

Пакеты v1/v2 доступны для чтения; для v2 нужны также исходные бинарные вложения. Для новых пакетов требуется RepoSync с поддержкой v3.

## Сборка

```sh
npm run build
npm start
```

`npm run build` обновляет файлы проекта. Для сборки приложения и установочных архивов выполните `npm run dist:mac` на macOS или `npm run dist:win` на Windows. Результат находится в `release/`. Ранее скопированная версия приложения автоматически не обновляется.

Подпись настраивается отдельно. Автоматических публикаций и обновлений нет.

В просмотре изменений доступны отдельные фильтры CRLF/LF, отступов и пробелов в конце строк, пустых строк. Возле каждого показано число файлов, скрываемых этим фильтром отдельно; общий счётчик учитывает выбранное сочетание. Пробелы внутри строк и содержимое комментариев сохраняются. Фильтры меняют только список: пакет и применение сохраняют точные изменения. Режим «Рядом» выравнивает строки, штрихует пустую сторону вставок и выделяет изменённые слова.

Дополнительный режим «Как compare-projects» сворачивает последовательности пробелов, табуляции и переносов в один пробел, игнорируя пробелы по краям текста. Он заменяет три частных фильтра и показывает свой счётчик. Режим затрагивает пробелы внутри строковых значений и не доказывает равнозначность кода; точный перенос сохраняется.
