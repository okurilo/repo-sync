# RepoSync

Приложение для двух сценариев между уже существующими изолированными Git-репозиториями: получить внешние изменения внутрь и вынести внутренние изменения через пакеты `.md`. Git history и `.git` не переносятся; commit и push выполняются обычными Git-инструментами.

## Запуск и настройка

Нужны Node.js **22.14+** и системный Git в `PATH`. Авторизацию внешнего Git настройте через SSH Agent или Git Credential Manager вне RepoSync.

```sh
npm install
npm run dev
```

Нажмите «Добавить репозиторий». Для внутреннего профиля укажите название, локальную папку/ветку и внешний Git URL/ветку. Для внешнего — название и локальную папку/ветку. Тип принадлежит репозиторию, глобального режима приложения нет.

Поля веток поддерживают поиск, загрузку и повтор после ошибки; выбор в RepoSync не переключает текущую Git-ветку. В «Дополнительно» находятся exclusions (glob по одному на строку), максимальный размер части и читаемый/компактный формат. Компактный выбран по умолчанию.

## Получить изменения

«Получить изменения» → просмотрите diff и отметьте файлы → «Применить изменения».

По умолчанию приложение сравнивает внешний branch HEAD с единственным общим предком выбранной ветки и её основы. Ветка и основа видны; основа определяется по Git HEAD, иначе выбирается явно. Проверка применения запускается автоматически после сравнения и изменения галочек. После проверки «До» показывает локальное содержимое, «После» — готовую внешнюю версию. До завершения проверки применение недоступно.

Выбранный изменяемый файл заменяется целиком, включая локальные правки в нём; отсутствующий создаётся. Неотмеченные файлы и пути вне diff сохраняются. Уже достигнутый результат пропускается. Конфликтующие добавления, удаления и переименования останавливаются до записи. Перед записью создаётся резервная копия и повторяются проверки файлов и веток. КБ-проверки во входящем сценарии нет.

«Другой способ / настройка ветки» раскрывает ветки и дополнительные сравнения: коммит относительно первого родителя, прямое A → B, сравнение репозиториев целиком или добавление от нуля. Полное сравнение включает удаления локальных файлов, отсутствующих снаружи; нулевое состояние не перезаписывает отличающиеся существующие файлы. Отсутствие/неоднозначность общего предка не заменяется полным сравнением молча.

Локальная рабочая копия должна быть на настроенной ветке. После применения проверьте результат и создайте коммит перед подготовкой исходящего пакета.

## Подготовить пакет изменений

«Подготовить пакет» → просмотрите отличия внутреннего committed HEAD от выбранного внешнего HEAD → отметьте файлы → «Создать пакет».

RepoSync сравнивает уже существующие репозитории независимо от их Git-историй. Общая сохранённая точка и первичный полный перенос не требуются. В новый пакет входят **только выбранные изменённые файлы**, каждый целиком; неизменённые файлы проекта не передаются и не перечисляются в пакете. Удаления и переименования — отдельные операции. Удаления по умолчанию не отмечены: отсутствие внешнего файла внутри само по себе не даёт согласия удалить его снаружи.

Папка экспорта выбирается один раз и сохраняется. Размер, число частей и папка показаны рядом с действием. Проверка данных выбранных файлов выполняется автоматически. Без срабатываний отдельного экрана проверки нет; при срабатываниях нажмите «Рассмотреть найденные данные», примите решения и создайте пакет оттуда. Возможные пароли, токены и ключи требуют отдельного явного разрешения; массовая галочка его не заменяет.

Передайте все части `.md` с исходными именами. На внешнем компьютере: «Выбрать пакет» → выберите любую часть → просмотрите и отметьте файлы → «Применить изменения». Все части должны лежать в одной папке. Проверка применения автоматическая. Новый пакет не требует исходного commit или общего состояния; выбранные изменяемые файлы заменяются целиком, остальные сохраняются.

После получения файлов снаружи вернитесь внутрь и нажмите «Подтвердить применение». Ожидание блокирует новые переносы; отмена ожидания сохраняет файлы пакета и не отменяет внешнее применение. Подтверждение нового пакета завершает ожидание и **не объявляет репозитории полностью одинаковыми**. Следующий пакет снова рассчитывается относительно актуальной внешней ветки; если она ещё не содержит перенесённые файлы, отличия будут предложены снова.

## Проверка данных и просмотр

Основные сценарии используют committed состояние выбранных веток. Staged/unstaged/untracked показаны отдельно и в пакет не входят. КБ-проверка рассматривает полные версии только выбранных исходящих файлов, включая содержимое переименований. Значения видны в просмотре; просмотр ничего не удаляет из пакета.

Можно оставить найденные значения, исключить файл или заменить значение в локальном исходнике. Исключение сохраняется в настройках. Замена требует подтверждения, затем обычного commit и нового сравнения. Scanner может пропустить чувствительные данные или отметить безопасный пример.

Галочки папок охватывают все вложенные операции, включая скрытые поиском и фильтрами. Переименование выбирается целиком. Поиск и фильтры CRLF/LF, отступов/краёв строк, пустых строк и «как compare-projects» меняют только просмотр, не выбранный набор или перенос. Последний режим также сворачивает пробелы внутри строк и не доказывает равнозначность кода.

Просмотр поддерживает поиск, сравнение рядом и единый список. Бинарные файлы и файлы больше 128 КБ выбираются без просмотра кода. SHA и технические сведения находятся в «Подробности»; доступны светлая и тёмная темы.

## Формат и совместимость

Новые пакеты используют protocol/schema **v5** с полными байтами выбранных изменённых файлов и без патчей. Текст открыт внутри `.md`; бинарные файлы передаются отдельными вложениями с исходными байтами и расширением. Переносите все части и вложения вместе. Base64, сжатия и шифрования при экспорте нет. Compact минифицирует служебные JSON-метаданные и убирает заголовки блоков; readable добавляет заголовки для просмотра. Содержимое файлов в обоих режимах неизменно: LF/CRLF, отступы, пробелы, BOM и executable mode сохраняются. Исходный Base64 в самих файлах также сохраняется. Размер части ограничивает `.md`; бинарное вложение остаётся целым, общий предел пакета — 512 МиБ.

Для новых пакетов обновите RepoSync на обеих сторонах. Импорт v1–v4 сохранён с прежними правилами исходного состояния; v2 также требует своих исходных бинарных вложений. Старые ожидания подтверждения сохраняют прежнее поведение. Настройки остаются v5; миграция v1–v4 сохраняет исходный JSON рядом с `settings.json`.

## Сборка

```sh
npm run build
npm start
```

Для `.app`/DMG/ZIP: `npm run dist:mac`; для Windows: `npm run dist:win`. Результат в `release/`. Сборка исходников не обновляет ранее скопированное приложение. Подпись настраивается отдельно; автоматического обновления нет.
