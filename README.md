# RepoSync

Приложение для двух сценариев между уже существующими изолированными Git-репозиториями: получить внешние изменения внутрь и вынести внутренние изменения через пакеты `.md`. Git history и `.git` не переносятся; commit и push выполняются обычными Git-инструментами.

## Запуск и настройка

Нужны Node.js **22.14+** и системный Git в `PATH`. Авторизацию внешнего Git настройте через SSH Agent или Git Credential Manager вне RepoSync.

```sh
npm ci
npm run dev
```

Нажмите «Добавить репозиторий». Для внутреннего профиля укажите название, локальную папку/ветку и внешний Git URL/ветку. Для внешнего — название и локальную папку/ветку. Тип принадлежит репозиторию, глобального режима приложения нет.

Поля веток поддерживают поиск, загрузку и повтор после ошибки; выбор в RepoSync не переключает текущую Git-ветку. В «Дополнительно» находятся максимальный размер части и читаемый/компактный формат. Исключения задаются в общих настройках и фильтрах рабочего экрана. Компактный выбран по умолчанию.

## Обновление приложения

Номер установленной версии виден рядом с названием приложения и в настройках: `v1.0.1` для main, `v1.0.1 · имя-ветки` для других веток. Выбор ветки обновления не меняет подпись текущей сборки.

При запуске RepoSync автоматически проверяет выбранную ветку. Если её коммит отличается от коммита работающей сборки, на главной появляется «Обновить приложение». В настройках можно выбрать ветку и вручную нажать «Проверить обновление». Кнопка «Обновить и перезапустить» появляется только при доступной версии. Фоновая проверка не блокирует работу с проектами и сама ничего не устанавливает.

Исходники определяются автоматически: сохранявшаяся папка, расположение приложения внутри repo-sync или служебная копия в папке данных. Невалидный старый путь не удаляется: приложение находит другой источник. Нужны Git и Node.js 22.14+ с npm; команда сборки выбирается из package.json под macOS/Windows. Несохранённые изменения, незавершённые Git-операции и расходящаяся история останавливают установку. Новая версия собирается отдельно, заменяет текущую после закрытия процесса и запускается; предыдущая сохраняется рядом. Для папки установки нужна запись.

На Windows заменяется папка установленного приложения (или win-unpacked) с сохранением штатного деинсталлятора; записи установщика в реестре не обновляются. Настройки и резервные копии RepoSync в папке данных не переносятся и не удаляются.

## Получить изменения

«Получить изменения» → выберите источник → «Показать изменения» → отметьте файлы → «Проверить выбранные файлы» → проверьте результат → «Применить изменения».

По умолчанию приложение сравнивает внешний branch HEAD с единственным общим предком выбранной ветки и её основы. Ветка и основа видны; основа определяется по Git HEAD, иначе выбирается явно. Сравнение запускается явно кнопкой «Показать изменения», после выбора источника. После изменения галочек нажмите «Проверить выбранные файлы». До проверки показываются исходная и конечная версии выбранного сравнения. После проверки выбранные файлы показывают «Локальную версию» и «Входящую версию»; невыбранные сохраняют исходное сравнение. До завершения проверки применение недоступно.

Способ «Две ветки» сравнивает вершины двух веток одного выбранного внешнего Git: исходная A → конечная B. Это прямой diff, без общего предка и без требования родства веток. Обе ветки выбираются явно; совпадающие ветки недоступны для сравнения. При изменении A или B перед применением требуется повторное сравнение.

Выбранный изменяемый файл заменяется целиком; отсутствующий создаётся. Незакоммиченные изменения вне выбранных операций не мешают применению. Перезапись затронутых рабочих версий требует отдельного подтверждения со списком файлов. Неотмеченные файлы и пути вне diff сохраняются. Уже достигнутый результат пропускается. Выбранные Git-операции принимают входящую версию автоматически, включая занятый путь добавления, удаление и оба пути переименования. Расхождения отмечены в дереве; при открытии показаны причина, реальные отличия и результат операции. Чтобы сохранить локальный файл, снимите выбор операции. Локальные версии сохраняются в резервной копии перед записью. Перед записью повторяются проверки файлов и веток. КБ-проверки во входящем сценарии нет.

На этапе «Источник» список «Что сравнить» позволяет выбрать дополнительные сравнения: коммит относительно первого родителя, прямое A → B, сравнение репозиториев целиком или добавление от нуля. Полное сравнение включает удаления локальных файлов, отсутствующих снаружи; нулевое состояние обновляет выбранные существующие пути входящими версиями. Отсутствие/неоднозначность общего предка не заменяется полным сравнением молча.

Локальная рабочая копия должна быть на выбранной ветке без конфликтов и незавершённых операций Git. При перезаписи staged-файла индекс сохраняется, изменяется только рабочая версия. После применения проверьте результат; коммит создаётся самостоятельно и не является условием подготовки следующего пакета.

## Восстановить предыдущие файлы

После применения доступна кнопка «Восстановить предыдущие файлы». Позже, включая после перезапуска, откройте «Резервные копии и восстановление» в подробностях карточки или на странице репозитория. Выберите операцию по дате, типу и ветке, посмотрите список путей и подтвердите восстановление. При большом наборе показаны первые 1000 путей, но восстановление затрагивает весь набор операции.

Восстановление возвращает только файлы и права этой операции: заменённые/удалённые версии возвращаются, созданные файлы удаляются. Git index, история и текущие настройки сохраняются; сведения синхронизации этого профиля сбрасываются. Состояние перед восстановлением тоже сохраняется в новой копии. Последующие изменения файлов или прав, другая ветка и повреждённая копия останавливают восстановление до записи.

Копии хранятся в `backups/<UUID>` внутри папки данных RepoSync; точное расположение показано в списке. `.bin` содержат исходные байты, `journal.json` связывает их с путями и правами. Новые журналы версии 3 дописывают ход операции в `progress.log`; эта версия читает прежние журналы и копии версии 2. Для новых копий используйте RepoSync 1.0.12 или новее: более ранние версии не поддерживают этот формат. Старые копии без сведений о ветке и итоговых правах сохранены и видны, но автоматическое восстановление для них недоступно. Автоматический откат прерванных операций старого формата сохраняется.

## Подготовить пакет изменений

«Подготовить пакет» → выберите «Из коммита» или «Из рабочей копии» → «Показать изменения» → отметьте файлы → «Проверить выбранные файлы» → проверьте пакет и папку → «Создать пакет».

По умолчанию выбран последний коммит настроенной локальной ветки; можно выбрать другой коммит из её истории. Рабочая копия включает текущие версии с диска, незакоммиченные правки, удаления и новые неигнорируемые файлы. Staged-файлы также читаются с диска, а не из индекса. Исключения проекта и явное включение игнорируемых файлов сохраняются. Выбор источника действует только для текущей подготовки. Просмотр, проверка данных и пакет используют сохранённые байты; изменение выбранных файлов перед экспортом требует повторной подготовки.

Если внутренний `master` продвинулся после переноса во внешний контур, выберите «Сравнить две версии Git»: A — старый внутренний коммит, B — актуальная вершина внутреннего `master`. В пакет попадёт прямой diff A → B с исходными версиями выбранных файлов. Во внешнем репозитории v7 объединит эти изменения с независимыми правками; после внешнего коммита вернитесь внутрь и получите результат сравнением внешней ветки с внутренней через обычный входящий сценарий.

RepoSync сравнивает уже существующие репозитории независимо от их Git-историй. Общая сохранённая точка и первичный полный перенос не требуются. В новый пакет входят **только выбранные изменённые файлы**, каждый целиком; неизменённые файлы проекта не передаются и не перечисляются в пакете. Удаления и переименования — отдельные операции. Удаления по умолчанию не отмечены: отсутствие внешнего файла внутри само по себе не даёт согласия удалить его снаружи.

Папка экспорта выбирается один раз и сохраняется. Размер, число частей и папка показаны рядом с действием. После выбора нажмите «Проверить выбранные файлы». Изменение галочек сбрасывает готовность пакета и решения проверки. Этап «Проверка» всегда показывает сводку и папку назначения. При срабатываниях там же доступны решения по чувствительным данным. «Назад к файлам» сохраняет выбор; изменение набора требует новой проверки. Возможные пароли, токены и ключи требуют отдельного явного разрешения; массовая галочка его не заменяет.

Передайте все части `.md` с исходными именами и бинарные вложения рядом. На внешнем компьютере выберите пакет, отметьте файлы и нажмите «Проверить выбранные файлы». Для обычных пакетов входящая версия заменяет выбранный файл целиком. Для v7 RepoSync до применения объединяет текст с локальными изменениями: пересекающиеся правки покажет отдельно; «Принять входящую версию» или «Оставить локальную» разрешает каждый конфликт. Нерешённые конфликты блокируют применение. Остальные пути сохраняются.

После получения файлов снаружи вернитесь внутрь и нажмите «Подтвердить применение». Ожидание блокирует новые переносы; отмена ожидания сохраняет файлы пакета и не отменяет внешнее применение. Подтверждение нового пакета завершает ожидание и **не объявляет репозитории полностью одинаковыми**. Следующий пакет снова рассчитывается относительно актуальной внешней ветки; если она ещё не содержит перенесённые файлы, отличия будут предложены снова.

## Проверка данных и просмотр

Входящие сравнения используют committed состояния выбранных веток. Исходящий режим коммита не включает рабочие изменения; режим рабочей копии включает текущие версии выбранных файлов. КБ-проверка рассматривает полные версии только выбранных исходящих файлов, включая содержимое переименований. Значения видны в просмотре; просмотр ничего не удаляет из пакета.

Проверка данных показывает общую ленту файлов с поиском по папкам, путям и контексту. Для совпадения выберите «Оставить значение» или «Заменить на *». Замена действует только в выгрузке и отменяется до её создания; исходник и Git не изменяются. «Исключить файл» оставляет его в ленте приглушённым, «Вернуть файл» восстанавливает сохранённые решения. Эти ручные исключения относятся к текущему пакету. Массовые действия при поиске затрагивают только найденные совпадения. Нижняя сводка показывает файлы, исключения, замены и нерешённые совпадения. Scanner может пропустить чувствительные данные или отметить безопасный пример.

Галочки папок и «Выбрать показанные»/«Снять показанные» затрагивают только показанные доступные файлы, сохраняя выбор вне поиска. Переименование выбирается целиком. Поиск и фильтры CRLF/LF, отступов/краёв строк, пустых строк и «как compare-projects» меняют только просмотр, не выбранный набор или перенос. Последний режим также сворачивает пробелы внутри строк и не доказывает равнозначность кода.

Просмотр поддерживает поиск, сравнение рядом и единый список. Для бинарных файлов и файлов больше 128 КБ вместо кода показаны наличие, размер, права и результат операции. Отмеченные расхождения не скрываются фильтрами пробелов. SHA и технические сведения находятся в «Подробности»; доступны светлая и тёмная темы.


## Общие и проектные фильтры

В настройках программы задайте шаблон glob-исключений, по одной маске на строку: например `**/*.test.*`, `**/*.snapshot`, `**/__snapshots__/**`. В «Настройках просмотра» рабочего экрана доступны унаследованные правила с переключателями и дополнительные маски проекта. «Сбросить настройки проекта» возвращает наследование. Правила сохраняются и применяются при подготовке пакета, получении из Git и применении пакета. Путь относительно корня, разделитель `/`, dot-файлы учитываются; отрицание `!` не поддерживается.

Совпавшие файлы остаются видимыми отключёнными: их нельзя выбрать, они не отправляются и не применяются. При переименовании учитываются оба пути. Снятие маски делает файл доступным, но не выбирает его автоматически. Изменение правил пересчитывает сравнение и сбрасывает готовность применения. Фильтры пробелов остаются отдельными настройками только просмотра.

## Сведения о проектах

Главный экран показывает тип и дату последнего успешного действия, состояние локального Git (текущая/настроенная ветка, SHA, дата коммита, рабочая копия) и загруженного внешнего Git. Фоновая проверка выполняется в простое при открытии приложения, возврате фокуса и раз в пять минут. Она использует список удалённых SHA, не загружает коммиты и не меняет рабочую копию. «Есть обновление» означает, что SHA отличается от кэша; кнопка «Обновить» загружает внешний Git только в кэш RepoSync. Ошибки и время последней успешной проверки показываются отдельно. Пока идёт работа с переносом, новые фоновые проверки не запускаются; устаревшие ответы отбрасываются.

Настройки v6 мигрируют прежние версии с резервной копией исходного JSON; прежние baseline, pending и legacy scope сохраняются. Типы действий включают сравнение, проверку данных, настройки, создание/применение пакета, подтверждение передачи и обновление кэша. Фоновые проверки не перезаписывают дату действий пользователя.

## Формат и совместимость

В подготовке пакета есть «Включать изображения в пакет», по умолчанию включено для новой сессии. Выключение исключает изображения, их удаления и переименования целиком; повторное включение возвращает индивидуальный выбор. SVG тоже считается изображением. Остальные файлы и существующие изображения получателя сохраняются. Код может ссылаться на исключённый ресурс: наличие зависимостей у получателя проверяйте отдельно.

Обычные пакеты используют protocol/schema **v6** с полными байтами выбранных изменённых файлов и без патчей. При сравнении внутренних версий A → B создаётся пакет **v7** с исходными байтами изменённых файлов для слияния с независимыми локальными правками. Непересекающиеся текстовые изменения объединяются автоматически; пересечения, бинарные и неоднозначные изменения требуют явного решения. Текст открыт внутри `.md`; бинарные версии передаются отдельными вложениями с исходными байтами и расширением. Переносите все части и вложения вместе. Отсутствующие бинарные вложения v5–v7 показываются предупреждением; отсутствующая исходная версия v7 блокирует загрузку. Повреждённые вложения блокируют загрузку. Base64, сжатия и шифрования при экспорте нет. V6 убирает повторяющееся описание файлов и вычисляемые поля; v7 сохраняет проверки размера и SHA256 для конечной и исходной версий. Compact минифицирует служебные JSON-метаданные; readable добавляет заголовки блоков. Кроме явно выбранных замен чувствительных значений на звёздочки в конечной версии, содержимое файлов сохраняет LF/CRLF, отступы, пробелы, BOM и executable mode. Исходный Base64 в самих файлах также сохраняется. Размер части ограничивает `.md`; бинарное вложение остаётся целым, общий предел пакета — 512 МиБ.

Для новых пакетов обновите RepoSync на обеих сторонах. Импорт v1–v6 сохранён с прежними правилами каждого формата; v2 также требует своих исходных бинарных вложений. Старые ожидания подтверждения сохраняют прежнее поведение. Настройки остаются v6; миграция v1–v5 сохраняет исходный JSON рядом с `settings.json`.

## Сборка

```sh
npm run build
npm start
```

Для `.app`/DMG/ZIP: `npm run dist:mac`; для Windows: `npm run dist:win`. Результат в `release/`. Сборка исходников не обновляет ранее скопированное приложение. Подпись настраивается отдельно; автоматического обновления нет.

## Контуры работы и локальный Git

«Внутренний» и «Внешний» — контуры работы. Во внутреннем настройте локальный репозиторий и внешний Git: изменения поступают из Git в локальную копию, а пакет создаётся для передачи во внешний контур. Во внешнем достаточно локальной папки Git: она и есть внешний репозиторий, в который применяется пакет.

При выборе папки RepoSync считывает текущую ветку. В существующем профиле выбранная ветка сохраняется; текущая ветка показывается отдельно. Перед применением видны обе ветки, HEAD, локальные изменения и незавершённые операции. При несовпадении можно нажать «Переключить на …»: только для существующей локальной ветки и чистой копии, без автоматического сохранения или удаления правок. После переключения просмотр проверяется заново.

В обоих контурах просмотр и применение доступны при локальных изменениях. Перед применением показаны затронутые незакоммиченные файлы; для их перезаписи нужна галочка «Разрешаю перезаписать перечисленные локальные изменения». Совпадающий результат не требует записи и подтверждения. Изменение выбранных файлов, их Git-статуса или HEAD после просмотра требует повторной проверки и нового согласия. Завершите или отмените незавершённые операции своими Git-инструментами, затем нажмите «Проверить снова». При detached HEAD выберите существующую ветку и переключитесь на неё. Перед записью повторяются проверки ветки, HEAD и файлов. Не изменяйте репозиторий параллельно с применением.

После применения изменения находятся в рабочей копии: проверьте результат и создайте коммит. Подтверждение передачи пакета завершает ожидание; оно не означает, что рабочая копия чистая или репозитории одинаковы.
