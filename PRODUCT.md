# RepoSync — контекст продукта

<!-- impeccable:product-schema 1 -->

## Platform

web

Интерфейс React внутри настольного Electron-приложения для macOS и Windows. Значение `web` описывает технологию и язык интерфейса; продукт используется как настольное приложение, а не как публичный сайт.

## Users

Основной пользователь — разработчик, который синхронизирует Git-репозитории.

## Product Purpose

RepoSync помогает сравнивать версии репозиториев, выбирать изменения и применять их после проверки. Неотмеченные пути сохраняются; коммиты и push пользователь выполняет своими Git-инструментами.

## Positioning

Настольное приложение для синхронизации Git-репозиториев с просмотром изменений и контролем результата.

## Operating Context

- Пользователь добавляет репозиторий, выбирает источник и файлы, просматривает различия, проверяет результат и подтверждает применение.
- Для каждого профиля сохраняются путь, ветка и настройки источника.
- После применения доступны резервные копии и восстановление файлов.
- Авторизация Git настраивается вне RepoSync; локальный запуск разработки описан в `README.md`.

## Capabilities and Constraints

- Исходящий пакет использует выбранный коммит либо текущую рабочую копию. В режиме рабочей копии учитываются staged/unstaged правки с диска, удаления и новые неигнорируемые файлы.
- Галочка «Включать изображения в пакет» включена при начале каждой сессии. Отключение исключает операции с изображениями, включая удаления и переименования с изображением на любом конце, и пересчитывает размер и проверку выбранного набора. Индивидуальный выбор изображений сохраняется при повторном включении.
- Перед применением требуется выбранная ветка без конфликтов и незавершённых операций Git. Посторонние рабочие изменения сохраняются; перезапись затронутых незакоммиченных файлов требует согласия по списку. Перед записью повторяются проверки ветки, HEAD и файлов, создаётся резервная копия; предусмотрено восстановление незавершённого применения.
- Изменяемые выбранные файлы переносятся целиком. При A → B непересекающиеся текстовые изменения объединяются с локальной версией; пересечения, бинарные изменения и неоднозначные операции требуют решения до записи. Сохраняются байты, LF/CRLF, отступы, пробелы, BOM, отсутствие завершающего переноса и executable mode.
- Новый экспорт не добавляет Base64, сжатие, шифрование или обфускацию. Уже существующий Base64 внутри исходного файла сохраняется как исходное содержимое.
- Текст находится открыто в `.md`; бинарные файлы — отдельные вложения с исходными байтами. Компактный режим уменьшает только служебные метаданные. Общий предел пакета — 512 МиБ.
- Проверка чувствительных данных выполняется для выбранных исходящих файлов. Scanner может ошибаться; потенциальные секреты требуют отдельного явного решения. При применении изменений из Git эта проверка не выполняется.
- Просмотр не маскирует исходные значения и не меняет передаваемые данные. Поиск и фильтры отличий влияют только на просмотр. Удаления в исходящем сценарии по умолчанию не выбраны.
- При запуске выполняется фоновая проверка обновления RepoSync; в настройках доступны выбор ветки и одна ручная «Проверить обновление». Кнопки обновления появляются только при отличающемся коммите выбранной ветки. Сборка и перезапуск запускаются пользователем; фоновой установки, автоматических commit/push, telemetry нет.
- Symlinks, submodules и неподдерживаемые пути или переходы типов файлов отклоняются, а не эмулируются молча.
- Дополнительные продуктовые требования доступности и конкретный стандарт соответствия пока не определены.

## Brand Commitments

Название — RepoSync. Интерфейс и пользовательские объяснения — на русском языке. Типы профилей называются «Локальный» и «Удалённый», источник Git — «Удалённый Git». Текст должен ясно объяснять результат действия, причину отказа и следующий шаг.

Не приписывать продукту неподтверждённые сертификаты DLP, гарантии scanner или результаты проверки платформ, отсутствующие в документации.

## Product Principles

1. Пользователь явно выбирает переносимые изменения и контролирует последствия применения.
2. Точность файлов и прозрачность содержимого важнее компактности пакета.
3. При неопределённости или конфликте остановить запись и объяснить причину; не подменять сценарий молча.
4. Оставлять управление Git-историей пользователю.
5. Использовать минимальный надёжный механизм без дополнительных слоёв и скрытых побочных эффектов.
