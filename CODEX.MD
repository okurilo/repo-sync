# Инженерный контекст RepoSync

## 2026-10-05 — реализация v1

- Репозиторий начинался пустым. Пользователь явно согласовал масштаб новой v1 сверх 10 runtime-файлов / 300 строк. Коммиты и публикация не запрашивались.
- Исходное ТЗ и приложенная инструкция сохранены в `docs/`. Применены strict TypeScript, именованные exports, отсутствие `any` и object syntax styled-components.
- Автоматические тесты и тестовая инфраструктура не добавляются по инструкции пользователя. Проверки: typecheck, Vite build, компиляция Electron Main/preload, упаковка и ручные сценарии.
- Минимальный механизм: системный Git без shell → committed inventory → lossless records → локальный Scan → `.md` parts. Import полностью готовит результат в памяти до backup и Apply.
- Важные решения и ограничения описаны в ADR/specs. Не добавлять hidden redaction, автоматические commits/push, telemetry, auto-updater и форматирование payload.
- Пользователь уточнил, что SHA — идентификатор выбранного Git commit, а его просьба об упрощении относилась к киберрискам. В обоих контурах добавлены загрузка веток, список 256 commits и explicit commit selection. Ошибочную трактовку как запрет функционального foreign baseline убрали: Import сохраняет путь local repository, его файлы могут служить baseline, если commit отсутствует в source Git. Отдельного source cache / commit mapping не добавляется.
- Local Diff с uncommitted payload не реализуется: ТЗ допускает отдельный workflow, но не требует его. Статусы staged/unstaged/untracked доступны, основной перенос — committed states.
- Symlinks, submodules, конфликт файла/каталога и несовместимые с Windows пути отклоняются; не эмулировать их молча.
- Scope fingerprint защищает от построения Diff после изменения exclusions. Вручную возвращённые ignored files используют content state и localRepository baseline; если baseline bytes изменены, нужен Snapshot.
- Импорт не коммитит изменения и не изменяет Git index. Настройки и backup journals пишутся Main атомарно. Startup recovery откатывает незавершённый Apply; конфликт с посторонними bytes останавливает recovery.
- Git fetch не делает автоматических retries: пользователь повторяет явную операцию после ошибки. Timeout 120 s, остановка дерева Git/helper процессов на timeout/quit; Git stderr не сохраняется, credentials не отображаются. Local fsmonitor hooks отключены.
- Журнал восстановления защищает от закрытия/падения процесса. Это не гарантия целостности при внезапном отказе диска/питания: для неё потребовалась бы отдельная модель durability.

## Единый список рисков комплексной проверки

1. Bytes / line endings / executable mode — encode/decode lossless, patch fuzz=0 и отключённая конверсия EOL, before/after SHA256, inventory verification.
2. Baseline / изменённые exclusions — commit читается из выбранного Git source; при отсутствии используется импортированный localRepository. Before hashes и scope fingerprint обеспечивают корректность Diff.
3. Несовместимые/повторные пути, traversal и symlink escape — проверка manifest и всех существующих компонентов пути; case-insensitive collision и конфликт файл/каталог отклоняются.
4. Компрессионные и oversized payload — 512 MB логического и восстановленного состояния, bounded Brotli decode, 10 000 parts / 100 000 records.
5. Потерянные/повреждённые/дублирующие части — UUID, единый manifest, part и package SHA256, полный набор перед изменениями.
6. Ошибка записи / частичный Apply / падение процесса — backup до mutation, intent journal и startup recovery; touched-only rollback.
7. Внешняя запись во время preview/Apply/recovery — повторный preflight и проверки перед каждой операцией и после; посторонние bytes не перезаписываются rollback.
8. Background I/O и credentials — один foreground IPC request одновременно, отдельная фоновая проверка refs с очередью fetch по repository, один экземпляр приложения, Git timeout/kill, no shell/hooks/prompts/redirects, Internal remote guard.
9. IPC / renderer network — sandbox, context isolation, allowlist команд, проверка sender/frame, CSP, запрет navigation/window/permissions, renderer file allowlist.
10. КБ значения в UI/настройках/логах — masked previews, приватные spans только в Main RAM; payload и backups конфиденциальны и хранятся локально.
11. Операционные ограничения — не изменять target во время Apply; неподдерживаемые типы файлов и shape transitions требуют ручного решения.

Результаты фактических проверок и остающиеся непроверенными платформы/сценарии фиксируются в `docs/manual-qa.md`.

- Settings schemaVersion 2 добавляет выбор commit в source и optional localRepository baseline. v1 мигрирует в v2 с branch HEAD по умолчанию, без изменения synchronized states. Transport protocol/schema остаются v1.

- Фактический масштаб исходников: 10 runtime TypeScript/TSX файлов, около 1 600 строк, плюс HTML и dev/build launchers; исходный repository был пустым. Сохранена простая process/infra/engine/UI граница без дополнительной базы states, telemetry, тестовой инфраструктуры или cloud слоёв.

- 2026-10-05: editor-подобный preview ограничен 6 runtime-файлами (около 180 новых строк, исходная оценка <300). Engine переиспользует readTree/buildDiff, preview имеет отдельную сессию без сохранения settings, pending или export token. UI ждёт 500 ms после выбора, выполняет Git/IPC последовательно с существующими операциями; устаревшие результаты не показываются. Код до/после передаётся только для открытого файла, ≤128 KB на сторону, binary/UTF-8 guard; existing Security Scan маскирует display values, payload не меняется. Renderer использует имеющийся diffLines (timeout 1 s), context folding и предел 2000 строк. Дерево показывает до 1000 совпадений, поиск доступен по полному списку. - 2026-10-05: управление Scan — 6 runtime-файлов, менее 100 новых строк (оценка 5/~100 уточнена до 6 из-за capability в security.ts). Причины disabled вычисляются из прежних условий; массовая кнопка заполняет existing kept IDs, override secrets остаётся отдельным. redactFinding валидирует token+ID и точный span, заменяет только target bytes на ***, переводит MODIFY в полный REPLACE, пересчитывает inventory hashes/content state/Scan/parts до публикации нового token. После передачи отредактированного пакета автоматический last-sync Diff отправителя потребует Snapshot, если content baseline отсутствует; прямой A→B Diff остаётся доступен.
