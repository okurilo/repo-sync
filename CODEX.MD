## Единый список рисков комплексной проверки

1. Bytes / line endings / executable mode — encode/decode lossless, patch fuzz=0 и отключённая конверсия EOL, before/after SHA256, inventory verification.
2. Baseline / изменённые exclusions — commit читается из выбранного Git source; при отсутствии используется импортированный localRepository. Before hashes и scope fingerprint обеспечивают корректность Diff.
3. Несовместимые/повторные пути, traversal и symlink escape — проверка manifest и всех существующих компонентов пути; case-insensitive collision и конфликт файл/каталог отклоняются.
4. Компрессионные и oversized payload — 512 MB логического и восстановленного состояния, bounded Brotli decode, 10 000 parts / 100 000 records.
5. Потерянные/повреждённые/дублирующие части — UUID, единый manifest, part и package SHA256, полный набор перед изменениями.
6. Ошибка записи / частичный Apply / падение процесса — backup до mutation, intent journal и startup recovery; touched-only rollback.
7. Внешняя запись во время preview/Apply/recovery — повторный preflight и проверки перед каждой операцией и после; посторонние bytes не перезаписываются rollback.
8. Background I/O и credentials — один foreground IPC request одновременно, отдельная фоновая проверка refs с очередью fetch по repository, один экземпляр приложения, Git timeout/kill, no shell/hooks/prompts/redirects, Internal remote guard.
9. IPC / renderer network — sandbox, context isolation, allowlist команд, проверка sender/frame, CSP, запрет navigation/window/permissions, renderer file allowlist.
10. КБ значения в UI/настройках/логах — masked previews, приватные spans только в Main RAM; payload и backups конфиденциальны и хранятся локально.
11. Операционные ограничения — не изменять target во время Apply; неподдерживаемые типы файлов и shape transitions требуют ручного решения.
